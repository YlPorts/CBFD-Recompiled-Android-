## Changes

- Query the Vulkan `dualSrcBlend` feature. Use original dual-source shaders on supported devices and a single-source-compatible path otherwise. Both dynamic and specialized shader variants follow the device capability, and unsupported SRC1 factors are not requested. Six complete fallback fragment modules are included.
- The fallback retains the original combiner RGB and blend factor; it does not force water opacity or disable depth. **Coverage in blended N64 draws is approximate**, because one primary alpha output cannot independently carry both coverage and the blend factor. This limitation can affect coverage-based edges/effects. Non-blended draws retain their coverage path.
- Java/JNI foreground and Surface generation notifications gate new native drawing while unavailable. Retire framebuffer wrappers before image views; rebuild the Surface/swapchain on the current SDL native window after loss, including equal-size replacements. Recheck capabilities/format and use fresh semaphores. Failed recovery attempts are throttled rather than repeatedly querying a lost Surface.
- Replace busy-wait ring-buffer ownership loops with condition variables using the same barrier predicate. Wake waiters on shutdown under the shared mutex. Buffer ownership and game clock are not bypassed.
- Add a GPU timestamp between setup/RSP and drawing/framebuffer operations, using the existing query/wait. Preserve a 32-bit triangle index during winding reversal rather than truncating it to 8 bits.
- **Native-size Android Surface, fixed internal 2x, fullscreen Expand, 60 FPS target and native orbital camera are retained. No dynamic-resolution reduction, 720p cap, external driver, extra storage permission or graphics settings menu.**

The provided phone log showed nonzero camera updates but zero modifyXY/modifyZ in the affected excerpts: the previous screen-depth command correction was not active in those excerpts and did not establish a water fix. Timing data include waits and cannot be labelled pure CPU time.

## Verification

- Actual software Vulkan/SwiftShader rendered controlled triangles and read back 139264 RGBA32F components: zero mismatches, maximum observed error 0. Device dualSrcBlend was 0 and remained disabled. The production PSMain body was extracted verbatim, with controlled inner RasterPS outputs. **This tests the output/blend-factor/pipeline connection, not the full Conker combiner or a river frame.**
- All six FULL production fallback SPIR-V modules have no Index=1; original dual-source modules retain it. All six compiled fallback modules were found byte-for-byte in the final APK's libmain.so.
- 311 lifecycle assertions, including shutdown races.
- 1604 assertions per extracted production queue method fixture, checking blocking, ownership, wake-up and shutdown. Waiting-thread CPU was below 0.1 ms during at least 60 ms blocked in local runs. This is not a phone FPS benchmark.
- 353 real Plume swapchain-method assertions with mocked SDL/Vulkan, including lost/missing/replaced Surface and recovery; 40 surface-policy cases; 3 source integration assertions.
- Repeated prior importer (42), storage (16), touch (184), metrics (34 including 40000 concurrent samples), matching/clipping (35976), actual matcher/matrix (6001), render/orbit policies (29609), and original recompiled camera-routine comparison (52) checks. Counts are assertions/cases, not gameplay tests.
- Layered dependency patches peeled/reapplied repeatedly and touched-file SHA-256 hashes compared; no destructive reset/clean.

A whole-game experimental desktop probe was NOT accepted as graphics validation: SwiftShader hit signal 11 before and after the fallback; llvmpipe exited cleanly after 240 seconds / 14370 VI but captured black images. Android-only counters were inactive in that Linux probe. These attempts do not establish water rendering, phone performance, audio or gameplay correctness.
