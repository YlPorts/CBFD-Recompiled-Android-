# Android 0.1.3-alpha: cierre al iniciar RT64

## Causa comprobada

El registro del usuario en SM-A155M / Android 16 muestra que las bibliotecas cargan,
la validación de la ROM termina y SDL crea la ventana 2340x1080. Después el proceso
nativo aborta con una excepción de filesystem al crear `/data/.rt64`.

El adaptador fijaba `useConfigurationFile=false` pero dejaba `detectDataPath=true`.
El constructor del RT64 fijado detecta la carpeta de usuario y la crea incluso sin
usar el JSON de configuración. Esa detección de escritorio no sirve para Android.

## Corrección

- `rt64_storage.hpp` resuelve y crea una carpeta `rt64` dentro del `state` privado
  pasado por GameActivity desde `getFilesDir()`. No usa HOME ni una ruta global.
- El adaptador pasa `detectDataPath=false` y `dataPath` explícito antes de construir
  RT64. El perfil fijo sigue sin leer opciones gráficas externas.
- La ruta se comprueba también en SDL_main antes de crear los hilos del motor.
  Las excepciones de inicialización del constructor gráfico se registran y se
  convierten en un contexto fallido, en lugar de propagarse fuera de ese hilo.
- Se añaden hitos de diagnóstico para construcción RT64, setup Vulkan, primera
  lista de dibujo y primera actualización VI; se incorpora rt64/rt64.log al informe.
- Se corrigen las versiones Java, nativa y de empaquetado a 0.1.3-alpha / código 4.

No cambia la carpeta de ROM ni de partidas. No se añaden permisos, selectores de
FPS, drivers externos ni ajustes gráficos. Se conserva Expand, objetivo 60 FPS e
interno 2x. El objetivo de FPS no es una medición.

## Verificación efectuada

Compilación y enlace Release completos para Android ARM64 con NDK 28.0.13004108
/API mínima 26: correctos. Se recompiló el motor, no solo Java. Java contra API 35
y SDL 2.32.10, conversión DEX y empaquetado: correctos.

Pasaron 42 pruebas sintéticas de importación y 16 pruebas de la política de rutas.
Además se compiló la clase UserPaths del RT64 fijado en el host: con HOME=/data
reprodujo `/data/.rt64`; con la política explícita eligió la carpeta privada de
prueba y ubicó allí su log. Esta prueba NO ejecuta RT64/Vulkan ni Conker.

La APK incluye el libmain.so nuevo; se verificaron su ABI AArch64, las entradas
SDL/JNI y los mensajes de la corrección. Se comprobaron firma v2/v3, certificado
idéntico al de 0.1.2 y alineación ZIP/ELF de 16 KiB de las tres bibliotecas.

APK: `Conker-Recompiled-0.1.3-alpha-arm64.apk` (20,628,075 bytes).
SHA-256: `4cfd95dc63c87828b9834b55c8d5adc6572a039ab6ba9858d5b5e93666f41e93`.
