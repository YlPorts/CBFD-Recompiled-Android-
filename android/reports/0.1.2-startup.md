# Android 0.1.2-alpha: corrección del cierre de inicio

## Fallo reproducido y cambio

El lanzador 0.1.1 fallaba antes de pedir la ROM. En un emulador Android 16 / API 36 se obtuvo un NullPointerException en PhoneWindow.getInsetsController, llamado por Immersive.apply antes de LauncherActivity.setContentView.

Reproducción: Actions run 36281814553, job 108514963308. La prueba usa las clases Java reales y sus recursos, sin ROM ni bibliotecas nativas: el fallo pertenece al arranque de la interfaz.

El commit 16085994c931ae1e207d14fa8801e88fbd487942 crea el decor antes de consultar el controlador, usa View.getWindowInsetsController() con comprobación de null y difiere el modo inmersivo hasta después de crear el contenido. También añade diagnóstico desde Application.onCreate, registro de carga de bibliotecas, historial de salidas de Android y recuperación antes de iniciar SDL.

La comprobación siguiente del selector usaba una espera fija de tres segundos; el log registra el inicio de PickActivity, pero la captura XML aún correspondía al lanzador. No se contó ese paso como aprobado.

Al volver se mostró el aviso del sistema de primera pantalla completa (Viewing full screen / Got it), documentado en la captura y en los IDs de SystemUI. Ese aviso impidió las aserciones restantes del test; el registro de cierres de la app siguió vacío. No se afirma que esta ejecución pasara las pruebas de cancelación y reanudación.

El commit 04a23160791738b53c0e985c18d5696ad96b95f4 solo modifica el test para pulsar el botón del tutorial de pantalla completa identificado por sus IDs de SystemUI; no acepta permisos ni descarta errores de la app. El resultado de esa regresión ampliada debe consultarse en Actions y no se presupone aquí.

**Estas comprobaciones no ejecutan Conker, Vulkan, audio o entrada nativa. No se han medido los FPS ni probado esta APK completa en un teléfono.** El perfil del motor mantiene su objetivo de presentación 60 FPS y widescreen adaptativo; no es una medición de 60 FPS.

## Instalación y conservación

Actualizar sobre 0.1.1 sin desinstalar ni borrar datos. Si el historial del cierre anterior muestra recuperación, usar Continuar a importar ROM; si ya existe la ROM, Volver a entrar. Tras otro cierre, Copiar diagnóstico incluye ahora errores anteriores a SDL.

No se publican la ROM, código generado del juego, APKs ni claves privadas en el repositorio. Se conserva el mismo respaldo privado de firma y código generado de 0.1.1. master no se modifica.
